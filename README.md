# 灰烬渡口

安装：`npm ci`

本地启动：`npm run dev`，打开终端显示的地址。

Docker 启动：`docker compose up --build`，访问 http://localhost:18071。

## 战斗档案：检查点 + 动作增量分块

旧实现每一步都保存完整前后快照，长战斗会迅速占满浏览器存储。现改为分块档案：

- **检查点 + 增量**：每个块只存一份完整检查点快照，块内各步仅存结构化动作增量
  （`src/features/replay/lib/delta.ts`），实测 30 步战斗档案体积约为旧快照档的 13%。
- **分块存储**：清单（manifest）+ 不可变定稿块 + 一个开放尾块，分别落在独立
  localStorage 键；尾块写满后定稿为新块并开启新尾块（默认每块 12 步）。
- **异步按需读取**：时间轴直接展示未加载/已加载/待存档/损坏区段；拖到远处时地图、
  编队与行动队列进入定位等待，对应检查点与增量重建成功后才整体切换。快速连续拖动
  通过令牌取消旧定位，只有最后一次请求生效。
- **播放不跳步**：跨块播放时等待数据读取与重建，定时器在异步步进完成前不推进。
- **原始步骤编号**：增量与元数据始终沿用录制时的逻辑编号，压缩、分块、迁移均不
  重新编号，下载记录与历史引用保持可对照。
- **损坏隔离**：块校验和不匹配或尾块结构损坏时，只标记受影响步骤区间，其余历史与
  实战指挥不受影响，可随时返回实战。
- **安全写入**：所有落盘走“临时键写入 → 回读校验 → 替换正式键 → 清理临时键”，
  绝不先删除原记录；写入失败（含配额不足）时旧档完整保留，内存动作不回滚，下一次
  行动自动重试。
- **旧档迁移**：启动时检测旧版完整快照档并自动压缩迁移；迁移全程成功后才删除旧档，
  压缩失败则继续保留旧档、下次启动重试。
